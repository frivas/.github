# Contributing

Thanks for taking the time to contribute.

## Before coding

- Search the existing issues first.
- Open an issue before a non-trivial change so the problem and scope are clear.
- Skip the issue only for obvious typo fixes or tiny maintenance changes.

## Build the change

- Work on a branch such as `feat/short-name`, `fix/short-name`, or `docs/short-name`.
- Keep each pull request focused on one outcome. A reviewable change is usually easier to test and merge than a large batch.
- Separate mechanical refactors from behavior changes when practical.
- Add or update tests for changed behavior.
- Update documentation in the same pull request, or send a focused docs-only pull request when that reads better.

## Open the pull request

- Explain what changed, why it changed, and how you tested it.
- Link the issue with `Closes #123` when the pull request resolves one.
- Call out risks, migrations, or rollback steps.
- Check the final diff for secrets, generated files, and unrelated edits.

Useful work matters more than activity volume. Do not split changes or create issues only to inflate contribution metrics.
